性能结论限定为资源上限与算法行为：TTL 写入淘汰 O(1)，图片缓存淘汰按被移除项数计费，图片内容保留量最多 64 MiB。没有实际线上流量基准，因此不宣称延迟或吞吐提升百分比。总进程 RSS、并发下载中的缓冲和磁盘缓存不包含在此内存缓存上限内。

## 兼容性与后续关注

- 任务 ID 作为不透明标识使用；本次检查的调用方不解析其格式。显式重复 ID 现在抛出 `job_id_already_exists`；同一活跃身份仍复用原任务。
- TTL 容量达到上限时可淘汰尚未过期的最早插入项，这是有意的容量政策；get 不改变淘汰顺序。图片超出总预算时可直接返回给请求方但不保留在内存，磁盘缓存行为继续保留。
- `server.js` 仍混合 HTTP 路由、图片选取与磁盘持久化，并在请求路径使用同步文件读写。建议下一轮以请求负载测量为依据，逐步拆分图片服务与异步存储；本次仅提取可独立验证的图片缓存职责。
- `route-composition-planner.mjs`、`search-intent-parser.mjs` 和 `routes.js` 仍是大型模块。后续应先补跨模块行为测试，再按策略选择、意图解析和页面状态拆分，避免一次迁移全部历史规则。
- 任务历史仍没有保留期限，图片磁盘缓存也没有整体字节预算。这些需要独立的保留/失效策略；本次未删除已有数据。
- 获取源码时 Git 大资源下载过慢，首轮省略 assets/vendor/legacy/data 等资源，用 skip-worktree 标记。后续浏览器验收已按原提交恢复并校验 assets/data/vendor 下 1,347 个资源文件；legacy 归档仍未加载，不构成提交删除。
- 没有修改已接受路线、生成缓存、知识库数据或发布开关。

## 2026-09-09 对抗性复审修复

在原审查范围上扩展检查静态服务、浏览器持久状态、异常 JSON、并发文件写入、后台任务取消、统计故障和发布检查前置条件。九项可复现问题均已关闭：

- 静态服务改用公开文件清单；`data` 仅开放世界地图实际请求的 `countries-50m.json` 与 `countries.zh.json`。`.git`、`.cache`、环境文件、服务端源码、测试、文档、知识原始数据、内部报告及图片审计文件不再可下载，授权判断发生在文件读取之前。
- 行程及共享弹窗的动态内容统一 HTML 转义；正常表单创建的注入载荷只显示为文字。
- 删除 `reset=empty` 的生产数据清空行为；畸形城市 hash 安全回退。
- Accepted 仓库以带版本、PID、进程启动身份、创建时间及随机 token 的路径锁串行修改，并在锁内重载最新文件。仅当完整元数据对应的 PID 可确认已死亡时才恢复遗留锁；活跃、畸形或无法确认的锁保持 fail-safe，避免旧实例覆盖新写入或重启后永久阻塞。
- 补库超时会取消底层工作，并在真实任务结束前保留去重占位。
- 统计写入失败不再使搜索失败；发现 API 严格验证 JSON 根类型、字段类型及列表容量，内部异常不再作为 details 返回。
- 依赖运行缓存或 Git LFS 数据的检查，在缺少前置条件时输出结构化 `BLOCKED` 并以状态码 2 退出；发布门禁不会把它计作通过。
